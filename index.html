Canvas 2D vs SVG DOM — 2D rendering benchmark

One scene model, one scene generator, one geometry cache, one configuration, one benchmark — and two interchangeable rendering backends. Open both pages, use the “open same config in …” link to carry the exact settings across, and compare.

Canvas 2D →

Immediate mode. Every frame re-issues all draw calls on a single <canvas>.

SVG DOM →

Retained mode. The scene is a real SVG element tree; a render creates or updates DOM nodes.

What the scene is

  • A room = a rectangle with one door opening, encoded as an open polyline of 6 points / 5 wall segments.
  • Every room contains 4 identical child rooms in a 2×2 grid, recursively, for a configurable number of levels.
  • Configurable margin between siblings and between children and the parent walls.
  • Leaf rooms (no children) carry an SVG icon.
  • Colours come cyclically from a 16 colour palette. The Scene panel's Transparent colours switch decides how a palette colour expands: on — one colour at alpha 1.0 / 0.8 / 0.2 for outline, wall body and room interior; off — three distinct opaque HSL shades.
  • Room count = (4levels − 1) / 3 — e.g. 5 levels = 341 rooms / 1 705 wall segments / 256 icons, 7 levels = 5 461 rooms / 27 305 walls.
  • The level count starts at 1 and is stepped up one at a time with ◀ ▶; there is no upper limit, and every extra level really does draw another, smaller generation of rooms. Wall thickness is clamped to 25 % of its own room, so no depth is ever geometrically impossible.
  • The only ceiling is the explicit Room budget in the Scene panel (default 200 000, enough for 9 levels = 87 381 rooms). Raise it to go deeper; the Levels built stat shows what was actually built.

What is measured

  • Measured: only renderer.renderScene() / renderer.renderFrame() — Canvas draw calls, or SVG DOM creation/attribute updates.
  • Not measured: scene generation, geometry preparation, colour derivation, icon parsing, UI work — all of it runs once per configuration change, outside every timer.
  • FPS comes from frames that were really rendered inside requestAnimationFrame, never from a synthetic timer.
  • The benchmark flips the backdrop black/white on every cycle, so you can see that each iteration really clears and rebuilds the whole scene.

Controls

  • Drag a single wall segment to deform its room. The two shared vertices move, the neighbouring segments stay attached, and the room's contents (child rooms, icons) do not move with it.
  • Drag an icon to move it.
  • Nothing else is draggable — whole rooms deliberately are not, so a drag never carries a whole subtree with it.
  • Drag anywhere else — including the inside of a room — to pan. Shift-drag and middle-drag always pan.
  • Wheel to zoom — the point under the cursor stays under the cursor.
  • Right click opens the browser's own context menu; it is never suppressed.
  • f fit to scene, r render once.
